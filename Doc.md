# Техническая документация проекта «Projects SPA»

## 1. Обзор архитектуры
**Projects SPA** — это одностраничное веб-приложение (Single Page Application) для управления проектами, задачами и изменениями. 

Приложение построено на **чистом JavaScript (Vanilla JS с использованием ES Modules)** без использования тяжеловесных фреймворков (React, Vue, Angular). Это обеспечивает высокую производительность, мгновенную загрузку и полный контроль над DOM.

### Основной стек технологий:
- **Язык программирования**: JavaScript (ES6+), HTML5, CSS3.
- **Модульная система**: Native ES Modules (`import` / `export`).
- **Хранение данных**: IndexedDB через легковесную обертку **Dexie.js**.
- **Файловая система**: File System Access API для автосохранения бэкапов напрямую на диск пользователя.
- **Архитектурный паттерн**: Глобальное состояние (State) + Событийная шина (Event Bus) + Реактивный ручной рендеринг.

## 3. Схема базы данных (IndexedDB / Dexie)

Вся бизнес-логика опирается на локальную базу данных, работающую прямо в браузере. База называется `AppDatabase`. Версионирование контролируется в `src/core/db.js`.

### Основные таблицы (Stores)
| Таблица | Описание | Индексы (Ключи для быстрого поиска) |
|---|---|---|
| `projects` | Проекты | `++id, num, name, statusId, priorityId, stageId, customerId, start, end, createdAt, updatedAt` |
| `tasks` | Задачи | `++id, num, name, projectId, statusId, priorityId, agentId, devId, customerId, start, end, createdAt, updatedAt` |
| `changes` | Изменения (Баги/Фичи) | `++id, num, name, taskId, statusId, priorityId, agentId, devId, customerId, start, end, createdAt, updatedAt` |
| `employees` | Сотрудники (Команда) | `++id, name, role` |
| `customers` | Заказчики | `++id, name` |
| `priorities` | Приоритеты | `++id, name, weight` |
| `taskStatuses` | Статусы задач/изменений | `++id, name, order` |
| `projectStatuses` | Статусы проектов | `++id, name` |
| `stages` | Стадии выполнения | `++id, name, order` |
| `stageHistory` | История перехода по стадиям | `++id, projectId, ts` |
| `kanbanBoards` | Кастомные Канбан-доски | `++id, module, name, createdAt, updatedAt` |
| `meta` | Ключ-значение настройки | `key` (Хранит `prefs`, `counters`, `lastSaved`, `fileHandle` и др.) |

> **Примечание:** Отношения между сущностями строятся по ID (например, `t.projectId === p.id`). В приложении нет сложных JOIN-запросов, так как данные загружаются в память (`refreshAll`) для мгновенного рендеринга.

## 4. Управление состоянием (State Management)

В приложении реализован паттерн "Единого источника истины" (Single Source of Truth) через глобальный объект состояния `S`.

1. **Загрузка данных**: При инициализации (`app.js`) вызывается функция `refreshAll(S)`, которая асинхронно выгружает все таблицы из IndexedDB в свойства объекта `S` (например, `S.projects`, `S.tasks`).
2. **Чтение**: Все функции рендеринга (страницы, компоненты) принимают объект `S` аргументом и строят DOM на его основе синхронно.
3. **Мутация**: 
   - Интерфейс **никогда** не мутирует объект `S` напрямую для сохранения данных.
   - Вместо этого UI-компоненты вызывают сервисные функции, которые обновляют IndexedDB (`db.projects.put()`).
   - После обновления БД вызывается `refreshAll(S)`, состояние в памяти обновляется, и UI перерисовывается.
4. **Хук `afterChange`**: Вызывается после любой транзакции на запись. Обновляет дату `lastSaved`, пересчитывает счетчики бейджей, и запускает триггер автосохранения.

## 5. Подсистема хранения и резервного копирования

Так как приложение хранит данные локально, безопасность данных — приоритет номер один.

### Механизмы сохранения:
1. **IndexedDB (Основной)**: Все данные немедленно пишутся в хранилище браузера.
2. **Экспорт/Импорт (Ручной)**: Создание JSON-слепка всей базы данных (`src/services/storage.js -> buildSnapshot`).
3. **Автосохранение (File System Access API)**:
   - Пользователь через настройки выбирает локальный `.json` файл на своем диске.
   - Дескриптор файла (`fileHandle`) сохраняется в `meta` БД.
   - Функция `autoSaveNow` автоматически перезаписывает этот файл при любом изменении данных с дебаунсом в 900мс (чтобы не спамить I/O операциями при быстром наборе текста).
   - При перезапуске приложения браузер запросит у пользователя разрешение (`queryPermission / requestPermission`) на продолжение записи в этот файл. Интерфейс запроса прав реализован в `settings.js`.

## 6. Основные компоненты (Представления)

Приложение поддерживает три глобальных представления данных:

### 1. Табличный вид (`src/components/table/`)
- Виртуализированный/ограниченный рендеринг для производительности.
- Поддерживает сортировку по колонкам.
- Поддерживает раскрывающиеся подстроки (Sub-rows) для отображения задач внутри проектов или изменений внутри задач.
- Полностью адаптивен (свайп по горизонтали на мобильных устройствах отключен, таблица масштабируется под `100%` ширины экрана).

### 2. Канбан-доска (`src/components/kanban/`)
- Распределение задач по статусам (`taskStatuses`).
- Поддержка кастомных досок с привязкой конкретных колонок.
- Реализован **Drag & Drop** (события `dragstart`, `dragover`, `drop`).
- Подсветка drop-зон, индикация превышения WIP-лимитов (Work In Progress).

### 3. Диаграмма Ганта (Таймлайн) (`src/components/timeline/`)
- Визуализация сроков (`start`, `end`) на сетке календаря.
- Расчет масштаба (Дни / Недели / Месяцы) через утилиты `date.js`.
- Интерактивный Drag & Drop самих полосок для смещения сроков задач или проектов.

## 7. Роутинг

Реализован самописный легковесный хэш-роутер (`src/core/router.js`).
- Маршрутизация основана на событии `hashchange` объекта `window`.
- Формат URL: `/#projects`, `/#tasks`, `/#settings`.
- Роутер использует Event Bus (`bus.emit('route:change')`) для уведомления `app.js` о необходимости перерендерить центральную контентную область (`#page`).

## 8. Соглашения по безопасности и качеству кода (Guidelines)

1. **Защита от XSS (Cross-Site Scripting)**:
   При генерации HTML через шаблонные строки (`innerHTML = \`<div...>\``), **каждая** переменная, содержащая пользовательский ввод, должна оборачиваться в утилиту `esc(str)` (находится в `dom.js`), которая экранирует HTML-сущности (`<`, `>`, `&`, `"`).
2. **Изоляция и делегирование событий**:
   Для списков и таблиц используется паттерн делегирования событий (один `addEventListener` на корневой контейнер `<tbody>` или списков), чтобы избежать утечек памяти и замедления работы приложения.
3. **Мобильная адаптивность**:
   - Никакого скролла по горизонтали на формах и канбане (используются `width: 100%`, `grid-template-columns: 1fr`).
   - Кнопки создания (FAB — Floating Action Button) фиксируются математически точно по центру с помощью `transform: translate(-50%, -50%)`.

## 9. Жизненный цикл добавления новой сущности

Пример добавления новой фичи "Теги":
1. **db.js**: Инкремент версии `db.version(X)`, добавление таблицы `tags: "++id, name, color"`.
2. **db.js (refreshAll)**: Добавление `db.tags.toArray()` в `Promise.all` и привязка к `S.tags`.
3. **refs.js**: Добавление вкладки "Теги" в UI управления справочниками. Создание формы добавления/удаления.
4. **storage.js**: Добавление `tags` в функцию `buildSnapshot` и список `tablesToSync` для экспорта/импорта.
5. Обновление UI компонентов для рендеринга чипов с тегами (с вызовом `esc()`).
